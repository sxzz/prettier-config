# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## Overview

Shareable Prettier config (`@sxzz/prettier-config`). ESM-only package. The entire config lives in `src/index.ts` and is bundled by tsdown into `dist/` (`index.mjs` + `index.d.mts`), which is what ships to npm.

## Commands

- `pnpm build` — Bundle with tsdown (`nodeLib` preset from `tsdown-preset-sxzz`, dts generated by `tsrs`)
- `pnpm lint` — ESLint with caching
- `pnpm format` — Prettier format all files
- `pnpm typecheck` — Type-check via `tsrs --fast`
- `pnpm release` — Version bump via `bumpp`

There is no test suite.

This repo formats itself with its own build output (`"prettier": "./dist/index.mjs"` in package.json), and `dist` is gitignored. Run `pnpm build` before `pnpm format` on a fresh checkout or after changing `src/index.ts`.

## Architecture

**`src/index.ts`** — The entire config. Default-exports an object (`satisfies Config`) with:

- Core rules: no semicolons, single quotes, trailing commas, 2-space indent (Prettier default)
- `overrides` array:
  - skips formatting generated/vendored files via `requirePragma`
  - uses the `json-stringify` parser for `jsr.json`
- `plugins` array built dynamically — always includes `@prettier/plugin-yuku`, conditionally adds framework-specific plugins via auto-detection

**Auto-detection pattern**: `isInstalled(pkg)` runs `require.resolve()` from `process.cwd()` to check whether a framework (e.g. `astro`) exists in the consumer's project. If it does, `resolvePlugin(pkg)` resolves the matching Prettier plugin; when that also succeeds, the plugin is pushed to `plugins` and its override (e.g. `*.astro` → `parser: 'astro'`) is added. Both steps fail silently.

**Dependencies**: `@prettier/plugin-yuku` is a regular `dependency` and always ships. Framework plugins (`prettier-plugin-astro`) are optional `peerDependencies` — the consumer installs them.

**Plugin resolution**: Uses `fileURLToPath(import.meta.resolve('...'))` to resolve plugin paths. Do not pass imported module objects directly — the path-based approach is intentional.

## Publishing

- Only `dist` is published (see `files` in package.json); `prepublishOnly` runs the build
- Scoped package published publicly (`publishConfig.access: "public"`)
- Release workflow triggers on `v*` tag push via GitHub Actions using `sxzz/workflows` (staged publish)
- Renovate auto-updates dependencies (`.github/renovate.json5`)
